# `إعدادات` — INI settings

```fa
من إعدادات استورد اعدادات_INI
اعدادات := اعدادات_INI().حلل("timeout=30\n[server]\nurl: https://host/?a=b\n")
تاكد(اعدادات.خذ("server"، "timeout"، عدم) = "30")
تاكد(اعدادات.خذ("server"، "url"، عدم) = "https://host/?a=b")
نسخة := اعدادات_INI().حلل(اعدادات.نص())
تاكد(نسخة.نص() = اعدادات.نص())
```

## API

| Operation | Behavior |
|---|---|
| `اعدادات_INI()` | Create settings with an empty `default` section. |
| `.حلل(النص)` | Merge parsed settings into this object and return it. Each call begins in `default`. |
| `.اقسام()` | Return section names, including `default`; order is unspecified. |
| `.خذ(القسم، المفتاح، البديل)` | Look in an existing section, then `default`, then return the fallback. A missing section returns the fallback directly. |
| `.ضع(القسم، المفتاح، القيمة)` | Validate names, create the section if needed, store `سلسلة(القيمة)`, and return this object. |
| `.نص()` | Serialize deterministically, or fail when a stored value cannot round-trip. |
| `اقرا_INI(المسار)` | Return a success result containing settings, or a failure result if reading the file fails. Syntax errors propagate as runtime errors. |

## Parsing rules

Lines use LF or CRLF. Blank lines and whole-line comments beginning with `#` or
`;` after trimming are ignored. Section names, keys, and values have surrounding
whitespace trimmed. Names are case-sensitive. `[default]` selects the default
section explicitly; empty named sections are preserved.

The **first** `=` or `:` separates a key from its value. Later separators remain
literal, so `url: https://host/?a=b` stores the complete URL. Empty values are
allowed. Inline `#` and `;` are literal value characters, not comments. Repeated
sections merge; the last assignment to a key wins. Parsing does not clear earlier
settings and is not transactional if a later line is invalid.

Section names must be nonempty and contain no brackets, CR, or LF. Keys must be
nonempty, contain no `=`, `:`, CR, or LF, and must not begin with `[`, `#`, or `;`.
Programmatically supplied names must also have no surrounding whitespace.
Malformed headers, missing separators, and invalid names raise runtime errors.

## Serialization and preservation

Defaults are always written before named sections, so they cannot accidentally
become entries in the preceding section. Named sections and each section's keys
are sorted using the language's string ordering. Output uses `key = value`, LF
line endings, and preserves empty named sections. Comments and original layout
are not retained. An entirely empty settings object serializes to empty text.

This INI dialect has no quoting, interpolation, escaping, or multiline values.
`.ضع(...)` may store text containing line breaks or surrounding whitespace for
in-memory use; `.نص()` rejects such values instead of changing them when read back.
Empty strings and internal whitespace are representable. For representable
settings, parsing serialized output preserves values, section membership, and
default lookup behavior; serializing again produces identical text.

## Semantic tests

`stdlib/tests/اختبار_إعدادات.ف` verifies separator precedence, duplicate keys,
merge behavior, defaults, empty values/sections, Unicode, deterministic output,
and serialization round trips. Public CLI rejection cases in
`tests/test_stdlib/test_stdlib_e2e.cpp` verify malformed input, invalid names, and
values that serialization cannot preserve, including exit status and diagnostics.
